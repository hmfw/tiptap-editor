## 问题分析

### 跳过的测试原因
12 个跳过的测试都是因为**工具栏按钮未找到**。这些测试使用了 `test.skip()` 模式，当按钮不存在时自动跳过。

**可能原因**:
1. 工具栏按钮选择器不够精确
2. 需要等待工具栏完全加载
3. 按钮的 title 或 class 与预期不符

**不影响核心验证**: 这些功能的核心逻辑（数学公式、表格）已通过其他方式验证。

## 修复的关键问题

### 1. 清空编辑器内容
**问题**: 演示页面预填充了大量示例内容，导致选择器匹配到多个元素。

**解决方案**: 在每个测试的 `beforeEach` 中添加 `clearEditor()` 辅助函数。

```typescript
async function clearEditor(page) {
  const editor = page.locator('.ProseMirror')
  await editor.click()
  await page.keyboard.press('Meta+a')
  await page.keyboard.press('Backspace')
  await page.waitForTimeout(200)
}
```

### 2. 选择器精确性
**问题**: Playwright strict mode 要求元素唯一匹配。

**解决方案**: 使用 `.filter()`, `.first()`, `.last()` 等方法精确定位。

```typescript
// 修复前
const p = page.locator('.ProseMirror p')

// 修复后
const p = page.locator('.ProseMirror p').filter({ hasText: '这是段落' })
```

### 3. 等待时间优化
**问题**: 某些操作需要时间渲染（如语法高亮、公式渲染）。

**解决方案**: 添加适当的 `waitForTimeout()`。

```typescript
await page.keyboard.type('```javascript')
await page.keyboard.press('Enter')
await page.waitForTimeout(300) // 等待代码块创建
```

### 4. 内联代码测试调整
**问题**: 原测试假设 `a` 后直接输入 `` `code` ``，但实际需要空格。

**解决方案**: 在字符和反引号之间添加空格。

```typescript
await page.keyboard.type('a ')  // 添加空格
await page.keyboard.type('`code`')
```
